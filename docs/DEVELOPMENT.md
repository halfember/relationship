# Local development

The local development setup runs MySQL and Redis in Docker. The NestJS API,
Vue web client, and mini program build run on the host so file watching and
debuggers work normally.

## Prerequisites

- Docker Desktop
- Node.js 20 or newer
- WeChat Developer Tools when debugging the mini program

## First-time setup

Start the infrastructure services from the repository root:

```powershell
docker compose -f docker-compose.dev.yml up -d
docker compose -f docker-compose.dev.yml ps
```

Create local configuration files if they do not already exist:

```powershell
Copy-Item server/.env.example server/.env
Copy-Item web/.env.example web/.env.local
Copy-Item miniapp/.env.example miniapp/.env.local
```

For the default development Compose configuration, set these values in
`server/.env`:

```dotenv
DATABASE_URL="mysql://root:relationship_dev@127.0.0.1:3306/relationship"
REDIS_URL="redis://127.0.0.1:6379"
PUBLIC_BASE_URL="http://localhost:3000"
AUTH_SECRET="relationship-local-development-secret"
NODE_ENV=development
PORT=3000
CORS_ORIGIN="http://localhost:5173"
```

Install dependencies and apply the committed database migrations:

```powershell
cd server
npm install
npm run prisma:generate
npm run prisma:migrate:prod

cd ../web
npm install

cd ../miniapp
npm install
```

## Run with hot reload

To start the infrastructure, apply migrations, and launch the API, web client,
and mini program watch build in the background, run from the repository root:

```powershell
.\scripts\start-local-dev.ps1
```

Runtime logs are written to `logs/local-dev`. Stop the host processes with:

```powershell
.\scripts\stop-local-dev.ps1
```

Pass `-StopInfrastructure` to also stop MySQL and Redis. Their data remains in
Docker volumes.

## Production release checks

The mini program uses environment-specific configuration. Build the production
artifact with `npm run check` or `npm run build:mp-weixin` after setting
`miniapp/.env.production` to the production API origin. Do not change source
code or enable `VITE_USE_MOCK_LOGIN` for a production build; production login
must use `wx.login()` and the server's configured `WECHAT_APPID` and
`WECHAT_SECRET`.

Before submitting for review, verify that every service category is reachable
from the home page, there are no placeholder buttons, test data, or unfinished
flows, and the submitted test account can exercise the complete account flow.

All user-authored text is checked by the server's content-safety interceptor,
and AI output is checked before it is returned. The local check is a baseline
guard only. Production must additionally configure and call the official WeChat
text/image security APIs before publishing user text or images; failures should
fail closed or place the content in a moderation queue.

Image URLs are currently public because WeChat `<image>` and
`previewImage` cannot attach Bearer headers. Treat uploaded images as
non-sensitive in the current deployment. A follow-up hardening change should
replace public URLs with short-lived signed URLs (or download-file flows with
temporary paths) before storing sensitive personal images in production.

Open separate terminals for the API and web client:

```powershell
cd server
npm run start:dev
```

```powershell
cd web
npm run dev
```

The API health endpoint is `http://localhost:3000/api/health` and the web
client is `http://localhost:5173`. Vite proxies `/api` requests to the API.

For mini program development, run:

```powershell
cd miniapp
npm run dev:mp-weixin
```

Open `miniapp/dist/dev/mp-weixin` in WeChat Developer Tools. The development
configuration enables `VITE_USE_MOCK_LOGIN`, which uses the backend's local
`dev_` login code so API flows do not require real WeChat credentials. Set it
to `false` and configure valid `WECHAT_APPID` and `WECHAT_SECRET` in
`server/.env` to test real WeChat login. For testing on a physical phone, change
`VITE_API_BASE_URL` in `miniapp/.env.local` to the development machine's LAN
address and configure the Developer Tools domain checks appropriately.

## Debugging

Attach a Node debugger to the NestJS process or run the existing `start:dev`
script from the IDE terminal. Source maps are generated by the Nest build.
Browser Vue Devtools can inspect the web client running through Vite.

Useful service commands:

```powershell
docker compose -f docker-compose.dev.yml logs -f mysql redis
docker compose -f docker-compose.dev.yml restart
docker compose -f docker-compose.dev.yml stop
docker compose -f docker-compose.dev.yml down
```

`down` preserves database and Redis data. Add `-v` only when intentionally
resetting all local development data.
