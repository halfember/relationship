# 小程序 V1.5 页面迭代设计

## 迭代目标

本次升级把产品从“功能入口集合”重构为“关系时间系统”。用户打开小程序后，应在 5 秒内知道三件事：最近该关心谁、还有多久、下一步能做什么。

核心用户任务按优先级排序：

1. 看见即将到来的生日、纪念日与共同事件。
2. 找到某个重要的人，回顾关系信息。
3. 快速添加关系、提醒或回忆。
4. 在需要表达或准备礼物时使用 AI。

## 信息架构

底部导航调整为“此刻、关系、中央记录、日历、我的”。AI 从一级目的地调整为具体人物和重要日中的情境能力，减少用户在开始任务前的功能判断。

| 页面 | 核心职责 | 首屏重点 |
| --- | --- | --- |
| 此刻 | 关系时间流 | 下一重要时刻、事件票据、关心圈、未来时间流 |
| 关系 | 感知与维护联系人 | 空间关系圈、分组名单、最近值得关心的人 |
| 日历 | 浏览和准备重要日 | 月历、日期议程、情境化准备动作 |
| AI 能力 | 生成表达与行动建议 | 从具体人物或事件进入祝福和礼物建议 |
| 我的 | 账户与服务管理 | 资料、共同空间、设置 |

## 核心设计决策

### 此刻

- 用大尺寸倒计时舞台承载下一重要时刻，并直接提供祝福和礼物准备入口。
- 后续事件使用可横向浏览的“事件票据”，建立时间推进感。
- 重要的人使用头像轨道呈现，7 天内有事件的人通过外圈强调。
- 未来安排使用纵向关系时间流组织，不再采用首页四宫格。
- 加载、无提醒、无关系均提供独立状态和明确下一步。

### 关系

- “关系圈”围绕当前用户空间化展示最多 6 个优先关系，优先级来自重要日和真实记录数。
- “名单”视图按关系类型分组，承担搜索、筛选与批量浏览。
- 两个视图共用搜索和类型筛选，但服务于不同认知任务。

### 关系日历

- 月历成为页面主导航，事件直接标记在具体日期上。
- 选中日期后只展示当天议程，也可切换到未来 90 天总览。
- 每条议程既能进入人物详情，也能直接准备祝福或礼物。
- 中央记录按钮统一承接添加人物、重要日和回忆三个动作。

## 视觉规范

- 主色：`#176B5B`，用于品牌、当前导航和主要行动。
- 强调色：`#E85D4A`，用于今天与紧急状态；`#F0C8A8` 用于日期重点。
- 背景：`#F5F6F4`；正文：`#202521`；弱信息：`#7B827E`。
- 页面以分隔线和留白组织信息，卡片仅用于需要明确边界的重点信息与状态。
- 卡片圆角不超过 `16rpx`，按钮触控高度不低于 `68rpx`，底部导航适配安全区。

## 验收与指标

上线前建议验证 320px、375px、430px 三档宽度，以及无数据、少量数据、长姓名、99+ 提醒四类极端状态。

建议在后续版本补充埋点，重点观察：

- 首页到提醒详情点击率。
- 添加关系、提醒、回忆的完成率。
- 关系列表搜索与筛选使用率。
- 事件发生前 7 天内的 AI 助手使用率。
- 新用户首次添加关系所需时长。

下一阶段优先级：先为首页重点事件增加“准备祝福 / 礼物建议”上下文入口，再补充提醒完成状态和最近联系记录。两项都需要后端增加明确的任务状态与联系行为数据后再设计，避免前端制造不可持续的伪状态。
