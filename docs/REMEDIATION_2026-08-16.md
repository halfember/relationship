# 全局审计修复记录（2026-08-16）

## 已完成

- 修正联系人邀请方向：接收者使用自己的称呼和关系类型，不再继承邀请人的私有备注。
- 统一邀请码入口按 8 位联系人码、10 位空间码分流；旧 6 位分享从运行时下线。
- 增加联系人邀请待处理列表、撤回、拒绝，以及联系人详情解除连接入口。
- 双人空间退出、解散、邀请撤回和过期时同步清理 `ContactConnection.sharedSpaceId`。
- 删除联系人时阻止绕过活动/待创建空间；移除空间邀请 `connectionId` 错绑入口。
- Web 管理端改为访问令牌登录、Bearer 鉴权、令牌主体绑定、401 退出；移除任意用户切换。
- Web 事件重复类型统一为 `每年`、`每月`、`每周`。
- 客户端无法修改 `vipLevel`；ValidationPipe 回归测试覆盖越权输入。
- 语音识别不再返回或保存假文本；缺配置、超时和上游异常分别返回 503、504、502。
- 新增统一上传存储服务；头像、私人/共享回忆替换、删除和账号注销会回收本地文件。
- 图片使用私有短缓存和 `nosniff`；登录、邀请、AI、语音、上传和图片读取加入限流。
- 数据库健康失败返回 HTTP 503；部署脚本同时验证 `healthy` 和版本号。
- 生产未知异常不向客户端暴露内部 message。
- 日程页统一使用 `utils/chinaHoliday.js`，移除重复节假日表。
- 接入微信订阅消息模板 2983，创建生日/纪念日时申请一次性授权，服务端按 `thing1/time2/thing4` 发送。
- 提醒增加原子认领、发送状态、最多 5 次退避重试、未授权识别和人工处理状态；只有微信成功响应才标记已送达。

- `server`: `npm run check`，包含编译、原回归测试和联系人/空间/隐私/语音/限流/健康检查新增测试。
- `web`: `npx vue-tsc -b`。

## 发布前操作

1. 在普通 PowerShell 中执行 `cd miniapp && npm run build:mp-weixin` 生成新的微信产物。
2. 使用新的服务端归档执行现有 Linux 发布脚本；脚本会备份数据库、执行检查和迁移、验证健康状态。
3. 在微信开发者工具验证联系人邀请接受/拒绝/撤回、双人空间退出、图片删除、账号注销和日程节假日。
4. 发布后检查 `/api/health` 返回 HTTP 200、`status=healthy` 和期望版本。

## 仍需外部条件

- 微信订阅消息代码闭环已接入；上线后仍必须用正式 AppID、模板和真实手机完成一次授权、送达、点击跳转验收，自动化测试不能替代微信侧验收。
- 限流当前适合单实例；横向扩容前需要 Redis 共享限流和统一审计日志。
- 图片以不可枚举 UUID 能力 URL 供微信原生图片组件访问；更高安全等级需要短期签名 URL 或鉴权图片代理。
- 节假日官方调休数据目前覆盖 2026 年；每年国务院安排发布后需更新唯一数据源。
- 备份仍需配置定时执行、异地保存、保留策略和定期恢复演练。
- 尚缺真实 MySQL/API E2E 测试；当前为 TypeScript 编译和服务层回归测试。
- 状态字段仍为字符串；后续数据库迁移可增加枚举/约束和管理操作审计表。
