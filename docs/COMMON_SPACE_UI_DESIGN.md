# 与你AI共同空间 UI 设计方案

> 状态：评审稿 V1.0  
> 范围：双人共同空间 P0、家庭空间 P1  
> 可视化原型：[打开 HTML 原型](./common-space-ui-prototype.html)

## 1. 设计目标

共同空间不是“把个人关系资料分享出去”，而是让双方明确创建一个共同维护的空间。界面必须持续传达三个信息：

1. 什么内容是共同可见的。
2. 什么内容仍然只属于自己。
3. 当前正在操作个人空间、双人空间还是家庭空间。

核心体验原则：

- 默认私密：用户未主动发布的内容不进入共同空间。
- 邀请有价值：邀请页要展示接受后能共同完成什么，而不是只展示邀请码。
- 空间有归属感：双人空间强调“我们”，家庭空间强调“我们的家”。
- 协作可追溯：共同内容显示发布人，成员和权限变更保留记录。
- 首屏可行动：每个空状态只提供一个最重要的下一步。

## 2. 信息架构

```text
首页
├─ 空间切换器（拥有共同空间后出现）
│  ├─ 个人空间
│  ├─ 双人空间
│  └─ 家庭空间（可多个）
├─ 近期提醒
├─ 快捷操作
└─ 最近关系 / 最近共同内容

关系
├─ 我的关系
├─ 共同空间
├─ 待处理邀请
└─ 添加
   ├─ 手动添加关系
   ├─ 邀请一起记录
   └─ 接受邀请

我的
├─ 共同空间管理
├─ 家庭空间
└─ 隐私与共享
```

底部导航维持现有五项：首页、关系、提醒、AI助手、我的。共同空间不新增底部导航项，避免六项导航造成拥挤。

## 3. 视觉系统

### 3.1 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `page` | `#F7F7FB` | 页面背景 |
| `surface` | `#FFFFFF` | 列表、表单、弹层 |
| `text-primary` | `#1F2333` | 标题和正文 |
| `text-secondary` | `#858897` | 辅助信息 |
| `border` | `#EDEDF4` | 分隔和边框 |
| `brand` | `#6C5CE7` | 主按钮、选中状态 |
| `brand-soft` | `#EFECFF` | 共同空间标签、提示背景 |
| `coral` | `#E96D68` | 纪念日、温暖强调 |
| `green` | `#4F9B6D` | 已接受、已完成 |
| `amber` | `#D9922E` | 待处理、即将到期 |
| `danger` | `#D85858` | 解除、移除、删除 |

不使用大面积紫色渐变。紫色只承担品牌和操作强调，家庭空间使用绿色、珊瑚色和蓝色辅助区分内容类型。

### 3.2 尺寸

- 页面左右边距：`28rpx`
- 区块间距：`24rpx`
- 列表项最小高度：`112rpx`
- 卡片圆角：`14-16rpx`
- 按钮圆角：`14rpx`
- 主按钮高度：`88rpx`
- 头像：列表 `72rpx`，详情 `104rpx`
- 固定底部操作区必须包含安全区高度。

### 3.3 字体层级

| 层级 | 字号 | 字重 |
|---|---:|---:|
| 页面标题 | `34rpx` | 700 |
| 区块标题 | `30rpx` | 700 |
| 列表主信息 | `26rpx` | 600 |
| 正文 | `24rpx` | 400 |
| 辅助信息 | `20rpx` | 400 |

## 4. 双人共同空间页面

### CS-01 添加关系操作面板

入口：关系列表右下角添加按钮。

操作面板提供三个动作：

- 邀请一起记录：主推荐项，说明“创建一个双方共同维护的空间”。
- 手动添加关系：保持现有个人关系流程。
- 接受邀请：输入邀请码的备用入口。

不得在点击添加后直接进入表单，否则用户无法理解手动关系与共同空间的区别。

### CS-02 发起邀请

字段顺序：

1. 对方称呼，必填，仅自己可见。
2. 我与对方的关系，必填，仅自己可见。
3. 共同空间名称，系统生成，可修改。
4. 共同纪念日，可跳过。

页面底部持续显示隐私说明：“你的私人备注、标签和AI记录不会分享给对方。”

主按钮文案：`生成邀请`。

### CS-03 微信邀请预览

邀请建立后展示微信分享预览，而不是把六位邀请码放在视觉中心。

主操作：`发送给微信好友`。  
次操作：`复制邀请码`、`撤回邀请`。

状态信息显示有效期和是否已被打开。

### CS-04 接受邀请

首屏包含：

- 邀请人头像和昵称。
- “邀请你一起记录彼此的重要时刻”。
- 已设置的共同空间名称和纪念日。
- 接受后可见的内容清单。
- 明确的隐私说明。

主按钮：`接受并进入空间`。  
次按钮：`暂不接受`。

未登录用户先完成微信快捷登录，登录成功后回到同一邀请页，不跳回首页。

### CS-05 双人空间首页

页面结构：

```text
空间名称 + 成员头像 + 设置
相伴天数 / 下一个纪念日
快捷操作：共同纪念日、共同回忆
近期纪念日
最近共同回忆
底部：添加共同内容
```

共同内容统一使用紫色“共同”标识；私人内容不出现在该页面。

共同回忆显示发布人，例如“由小雨添加”。编辑和删除入口放在更多菜单中，不直接暴露危险操作。

### CS-06 添加共同内容

使用底部操作面板选择：

- 添加共同纪念日
- 添加共同回忆

提交按钮上方显示可见范围：`发布后，小雨和你都能看到`。可见范围不设计成默认不明确的开关。

### CS-07 空间设置

设置项包括：

- 空间名称
- 成员与状态
- 我的称呼和关系类型
- 共同内容通知
- 导出共同内容
- 解除共同空间

解除属于危险操作，必须经过影响说明和二次确认。确认页说明私人内容保留、共同内容如何处理。

## 5. 家庭空间页面

### FS-01 家庭空间入口与空状态

“我的”页面展示家庭空间入口。未创建时进入独立空状态：

- 标题：“把家人的重要日子放在一起”
- 价值点：成员档案、生日提醒、家庭回忆
- 主按钮：`创建家庭空间`
- 次按钮：`接受家庭邀请`

不要先要求邀请成员。用户可以先建立档案并获得个人价值。

### FS-02 创建家庭空间

字段：

- 空间名称，默认“我们的家”。
- 空间头像，使用姓氏或自定义图片。
- 第一位家庭成员，默认当前用户。

创建成功后进入成员引导，提供“添加家人档案”和“邀请家人加入”两个明确选项。

### FS-03 家庭首页

第一视口必须明确显示家庭名称，不能只在导航栏显示小字。

页面结构：

```text
我们的家 + 空间切换
5位家人 · 2位已加入
本月重要日子
快捷操作：添加家人、纪念日、回忆
家庭成员横向列表
最近家庭回忆
```

家庭成员头像区只作为快速入口，不在头像下堆叠过多关系说明。

### FS-04 家庭成员

顶部采用分段控制：`全部 / 长辈 / 同辈 / 晚辈`。

成员列表区分两种状态：

- 已加入：显示账号头像和“已加入”。
- 档案成员：显示“仅档案”，并提供绑定邀请。

添加成员操作面板：

- 添加家人档案
- 邀请家人加入

### FS-05 添加家人档案

必填信息只有姓名、与我的关系。生日、头像、称呼均可稍后完善。

关系选择使用分组列表，不使用自由文本作为主入口。选择后提供“称呼不准确？手动修改”。系统推导结果必须允许修正。

### FS-06 家庭日历

默认显示列表而非传统月历，因为生日和纪念日更适合按时间扫描。

页面包含：

- `即将到来 / 全部`分段控制。
- 月份分组。
- 每项显示日期、事件、关联成员、剩余天数。
- 右下角添加按钮。

### FS-07 家庭回忆

默认采用双列图片流；纯文字内容占整行。每条内容显示日期、关联成员和发布人。

首版不加入点赞评论，更多菜单只提供编辑、保存图片和删除自己发布的内容。

### FS-08 家庭设置

包含：

- 空间资料
- 成员与权限
- 家庭提醒设置
- 邀请管理
- 导出家庭内容
- 退出家庭
- 转让创建者 / 解散家庭

只有创建者显示转让和解散操作。普通成员不显示无权限入口。

## 6. 空间切换器

触发条件：用户至少拥有一个双人或家庭空间。

点击首页当前空间名称，弹出底部空间选择器：

```text
个人空间
小雨和我                 双人
我们的家                 家庭
爸爸妈妈家               家庭
────────────────────────
创建家庭空间
```

当前空间使用勾选图标，不使用颜色作为唯一状态提示。切换后保留底部导航位置，只替换首页内容域。

## 7. 关键状态

所有页面需覆盖以下状态：

| 状态 | 处理方式 |
|---|---|
| 加载中 | 使用固定高度骨架，避免页面跳动 |
| 空状态 | 说明价值，只提供一个主动作 |
| 无网络 | 保留上次数据，顶部提示重新加载 |
| 邀请过期 | 显示邀请人信息和“联系对方重新邀请” |
| 邀请已使用 | 说明已加入对应空间并提供进入入口 |
| 无权限 | 不展示敏感内容，提供返回空间首页 |
| 成员被移除 | 清理本地空间缓存并回到个人空间 |
| 内容提交中 | 禁止重复提交，保留表单内容 |

## 8. 文案规范

推荐：

- “邀请一起记录”
- “共同空间”
- “发布后，你们都能看到”
- “你的私人记录不会分享”
- “家庭档案成员尚未加入与你AI”

避免：

- “邀请建立关系”
- “共享我的关系数据”
- “被管理人”
- “访客用户”
- “对方无权限”

## 9. 动效与反馈

- 接受邀请成功：成员头像合并为共同空间头像，时长 `240ms`。
- 空间切换：内容轻微淡出淡入，时长 `160ms`，不做横向整页滑动。
- 新增共同内容成功：返回列表后高亮新条目 `1.2s`。
- 危险操作不使用动画强化，保持克制。
- 所有按钮点击后立即进入加载状态，禁止重复提交。

## 10. UI 验收清单

- 每个共同页面都能识别当前空间和成员。
- 每个发布动作都明确说明可见范围。
- 私人字段不会出现在邀请预览或共同空间。
- 未登录接受邀请后能返回原邀请上下文。
- 超长家庭名称和成员姓名不会撑破布局。
- 页面在 320px 至 430px 宽度下无横向滚动。
- 固定按钮不遮挡内容和微信安全区。
- 空状态、过期状态、无权限状态均有明确下一步。
- 危险操作与普通操作不使用相同颜色和位置。
- 一个用户加入多个家庭空间时，切换和退出对象明确。
